# 读取与全量核对进度 · v1.3.4

沿用现有界面的紫色强调色、透明白色表面、细白边、圆角和柔和阴影。遵循项目安装的 UI UX Pro Max 关于进度反馈、真实状态、减少动态效果和可访问进度语义的指导。

## 展示方式

- 预览：在读取状态原有位置展示卡片，说明“只读取所选来源，尚未创建或移动视频”。
- 执行前：将相同卡片嵌入任务区域，暂时收起未开始的移动统计；核对结束后恢复移动与完整核对进度。
- 目标核对：显示当前目标的所有分页读取进度，完整比对通过后才计为完成；已通过的目标在后续目标核对时继续计入整体进度。
- 中转和校正：对位置核对所需的全量读取显示本次分页进度，每次重读重新开始。
- 执行后：卡片显示原来源的归属检查进度，移动与目标核对数量继续保留。
- 正常完成使用绿色状态；出错保留停止时的进度和当前来源，结合错误说明，不自动跳满。

## 计算与边界

来源整体进度为各收藏夹完成比例的平均值，明确标注“按收藏夹”，并显示已完成的来源数。不同大小的收藏夹等权，不声称是全任务耗时或精确视频总量比例。

当前夹使用实际分页返回的已读取条数和总数，另显示页数。读取开始时目录总数可提供初始范围，实际分页数据到达后替换；未知总数不设置 `aria-valuenow`。空夹收到实际空页并确认后完成。最后一页到达而来源尚未通过核对时，整体最多显示 99%。

有效缓存计入已经完成的来源；全部命中缓存的规则重算不闪现读取动画，也不增加请求。错误不会伪装成完成。读取阶段 100% 仅代表该阶段的来源已读取 / 核对，最终整理仍以目标和来源归属全部通过为准。

进度条使用 `role="progressbar"`、来源名称和完整数量文本，状态区域保留屏幕阅读器通知。填充仅使用短时 `transform` 过渡，尊重 `prefers-reduced-motion`，不使用持续闪烁。窄窗口内容自然换行。

## 耗时

耗时位于任务标题下方，核对时可直接查看。活动任务每秒更新，等待分页返回时也更新；完成或停止后冻结。少于 60 秒用秒，达到 60 秒显示分秒，达到 3600 秒显示时分秒。例如 1327 秒为“22 分 7 秒”，3661 秒为“1 小时 1 分 1 秒”。仅更新本地显示，不用额外请求维持进度。

## 验证

- `npm test` 包含 11 项读取进度与耗时检查，总计 108 项回归。
- `npm run test:progress` 使用实际页面和模拟接口，验证预览 / 执行前核对 200 / 1000 = 20%，完成状态、缓存零请求、限流中断保留、390px 窄屏及减少动态效果。
- `npm run test:browser` 包含原完整管理页回归、框选回归和上述进度检查。
