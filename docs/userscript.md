# Bilibili 收藏夹自动整理脚本

这个仓库提供一个可直接在浏览器运行（Tampermonkey 或控制台）的脚本：

- 输入多个收藏夹名称；
- 统计这些收藏夹内每位 UP 主的视频数量；
- 按 UP 主出现数量自动分组并创建新收藏夹；
- 自动把视频移动到新收藏夹；
- 在现有 UI 内显示执行前确认弹窗、执行中实时进度、执行后结果弹窗。

> 仅处理你自己的视频收藏夹，依赖当前浏览器登录态（Cookie），不需要额外 API 凭证。

## 文件

- `bilibili_fav_auto_sort.user.js`：主脚本。

## 使用方式

1. 登录 B 站并打开「我的收藏夹」页面，URL 类似：
   `https://space.bilibili.com/<你的mid>/favlist`
2. 用 Tampermonkey 新建脚本并粘贴 `bilibili_fav_auto_sort.user.js` 内容（或直接在控制台执行 IIFE 主体代码）。
3. 运行脚本后，页面右下角会出现「收藏夹智能整理」按钮，点击后弹出可视化面板。
4. 在面板中填写：
   - 要处理的收藏夹名称（支持英文逗号、中文逗号、分号或换行分隔）；
   - 新收藏夹基础名称（默认自动名，长度≤10字符）；
   - 每个新收藏夹的视频上限（1-1000，可自定义，例如 800）。
5. 点击“开始执行”后流程如下：
   - **执行前确认**：在 UI 弹窗中显示“即将移动的视频数量、目标收藏夹数量、UP 主数量、分组计划”。
   - **执行中进度**：面板底部状态会实时刷新百分比和已处理数量（例如“移动视频 35%（15/43）”）。
   - **执行完成**：在 UI 弹窗中显示完成结果（成功数、失败数和新收藏夹信息）。
6. 脚本会按当前 B 站 Web 收藏夹接口自动创建私密目标收藏夹；如果创建接口临时返回“系统升级中，敬请谅解”，会自动使用兼容参数重试，并在存在同名目标收藏夹时复用。

### 取消与接口限流

- 在分组计划弹窗中点击“关闭”或右上角关闭按钮，会直接返回可操作的面板，不再刷新页面，也不会创建收藏夹或移动视频。
- 读取和写入请求共用串行队列，请求开始时间至少间隔 1.2 秒；多个源收藏夹依次读取，避免并发分页造成短时间大量请求。较大的收藏夹会比以前读取得慢。
- HTTP 412 / 429、已识别的接口风控码或频繁访问提示会立即停止任务，不再连续重试。脚本至少冷却 60 秒；若服务端给出更长的 `Retry-After`，则遵循该时间。冷却时间保存在当前站点本地存储中；站点存储不可用时只在当前页面生效。
- 冷却结束只代表脚本允许再次尝试，不保证 B 站服务已经恢复。若网页仍不可用，请等待，避免反复刷新、重复启动或多标签页同时运行。此限速只约束本页面的脚本请求，无法控制网页本身、其他标签页或其他工具的请求。
- 若读取分页失败，只重试失败页；分页重复或数据不完整时停止，不使用不完整数据执行移动。

取消前没有写入操作。原版本的并发读取、无间隔分页可能引发服务端限流，但仅凭现象无法确定真实原因。若更新后仍出现不可用，请记录发生阶段、持续时长、HTTP 状态或接口 `code` / `message`；不要分享 Cookie、CSRF 或完整请求头。

## 开发验证

无需构建或安装应用依赖。Node.js 下运行：

```sh
node --check bilibili_fav_auto_sort.user.js
node tests/request-safety.test.cjs
```

`request-safety.test.cjs` 使用模拟时钟和 API，验证读取限速、取消、冷却、重试范围、分页异常及完整整理流程。

浏览器回归测试需要 Playwright 1.56.1 和系统 Chromium（默认 `/usr/bin/chromium`），可将测试依赖安装到仓库外：

```sh
npm install --prefix /tmp/fav-sort-browser-tools --no-package-lock --no-save playwright@1.56.1
NODE_PATH=/tmp/fav-sort-browser-tools/node_modules node tests/browser-smoke.cjs
```

浏览器检查拦截页面及 B 站 API，验证界面交互；不会访问真实收藏夹。当前 Chrome / Edge 扩展需求草案见 [扩展需求](docs/extension-requirements.md)，尚未实现扩展。

## 分组规则

- B 站单收藏夹上限为 1000 视频；脚本支持你手动设置更小“目标上限”（例如 800）。
- 拆分时遵循「不拆分同一个 UP 主」原则：
  - 若当前目标收藏夹已接近上限，而下一个 UP 视频数量过多，则该 UP 会整体进入下一个目标收藏夹。
- 同一个 UP 主的视频会按视频发布时间排序：最近发布的视频排在前面，最早发布的视频排在后面；如果接口缺少发布时间，则回退使用收藏时间和标题排序。
- 为了让“视频更多的 UP 主”排在新收藏夹前几页，脚本会在移动时使用反向写入顺序（适配 B 站按最新收藏时间展示机制）。

## 当前使用的 B 站接口

- 获取收藏夹列表：`GET https://api.bilibili.com/x/v3/fav/folder/created/list-all`
- 读取收藏夹内容：`GET https://api.bilibili.com/x/v3/fav/resource/list`
- 新建目标收藏夹：`POST https://api.bilibili.com/x/v3/fav/folder/add`，表单参数包含 `title`、`privacy=1`、`csrf`。
- 移动收藏夹内容：`POST https://api.bilibili.com/x/v3/fav/resource/move`

## 注意事项

- 建议先用少量收藏夹做一次验证。
- 脚本行为是**移动**而不是复制。
- 收藏夹名需精确匹配（忽略大小写、前后空格）。
- 目标收藏夹会在移动视频前统一创建或复用；脚本默认创建私密收藏夹，并会先准备完全部目标收藏夹再开始移动，避免先移动一部分视频后再因创建失败中止。
- 若某个 UP 单独视频数量 > 1000，因平台上限无法做到完全不拆分，脚本会报错中止。
- 若接口变更导致失败，请根据浏览器网络面板抓包校验参数。
