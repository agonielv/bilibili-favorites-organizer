# 整理可靠性自查 · v1.3.2

日期：2026-11-06。检查对象为扩展运行文件，不含旧油猴脚本的新功能。测试使用模拟接口与内存后端，不操作真实账号。

## 本次复现与修复

| 问题 | 影响 | 修复与验证 |
| --- | --- | --- |
| 来源目录数量显示为零时跳过实际读取 | 在模拟复制式成功响应且目录计数滞后时，原来源仍有视频却报告完成 | 最终逐个实际读取来源，按视频与来源核对；目录显示零也不跳过 |
| 执行前只凭目录数量拒绝计划 | 实际内容未变、目录计数滞后也会要求重来 | 以全量来源读取为准；真实数量、视频、失效状态或排序字段变化仍阻止写入 |
| 目标与已有收藏夹同名到执行时才报错 | 反复整理时，扫描与确认之后才发现需要改名 | 预览给同名目标添加编号，确认展示实际名称；确认后出现的新冲突仍拒绝执行 |
| 没有在首次移动前检查新目标为空，创建返回 ID 未检查复用 | 异常接口响应可能使已有内容进入整理流程 | 新目标空夹检查、目标和中转 ID 唯一性检查；异常时停止，原有视频不参与校正 |
| 创建 API 返回 -403 时尝试其他表单 | 明确权限错误仍反复提交无用请求 | 单次请求后停止，保留明确错误 |

这些是代码与模拟故障中复现的逻辑问题，不表示它们都已发生在真实账号。

## 自动化覆盖

`npm test` 共 97 项检查，包括：

- 读取：空夹、失效收藏、未知日期、缩页、重复或缺失分页、读取途中数量变化、13 来源的 11,606 / 50,000 条长时间任务。
- 计划：分组与非分组、UP 排列、容量拆分、时间升降序、跨来源重复、仅保留副本的来源、目标命名。
- 移动：批量从 2 到 20 / 100、不同批量上限、拒绝前部分应用、成功响应只应用一部分、不同参数写入顺序、后半段乱序、中转与逐条回退。
- 数据归属：新目标 / 中转保护、原来源与目标唯一视频对应、重复副本与失效收藏保留、复制式伪成功、目录计数滞后。
- 账号与故障：来源同数量替换、失效状态变化、登录变化、风控、冷却、写入超时不重放、执行前失败零移动。
- 其中一项持续执行 **2,000 组固定种子组合**，交叉混合重复副本、失效标记、缺失日期、来源交错、排序规则、容量、公开 / 私密、批量上限、部分应用与后端排序。用独立归属计算核对每个来源的剩余项、全部目标顺序、总收藏记录守恒及中转清空。

`npm run test:browser` 使用实际 HTML / CSS / ES 模块与模拟 Chrome API，覆盖正常执行、重复与失效保留、第二次整理同名目标的只读预览、取消、缓存、长时读取、字段校验、进度、账号切换、冷却、任务锁，以及框选、反选、双向滚动、触屏和窄窗口面板。

`npm run benchmark` 的 6,000 条场景逐 ID 检查目标顺序；安全核对增加读取请求，但保留自适应批量移动。数据见 [请求量基准](transfer-benchmark.json)。

## 仍可能阻断或中断的情况

| 情况 | 当前行为 |
| --- | --- |
| 服务端限流 / 风控、账号失效或变化 | 停止并说明，冷却不自动续跑；不能保证服务端何时恢复 |
| 断网或写入响应不明确 | 停止，不自动重复写入；保留已知来源、目标和中转位置 |
| 任务中关页、浏览器退出或扩展被停用 | 不支持断点恢复；执行时需保持管理页打开 |
| 来源在预览后发生真实变化 | 全量核对后阻止写入，需重新读取生成计划 |
| UP 视频数超过容量且启用“不拆分” | 预览阶段明确提示，需要允许拆分或提高容量；容量最多 1,000 |
| 来源含非视频收藏 | 当前仍仅支持视频，需要单独处理该来源 |
| 收藏夹数量 / 服务端容量限制、接口规则变化 | 创建或移动可能被拒绝；报告实际错误和已完成状态，不假报成功 |
| 真实 Chrome / Edge 与 B 站现行接口 | 云环境浏览器使用 API shim，无法据此保证真实账号行为；未进行真实收藏写入验证 |

没有“所有情况必定成功”的保证。已经能自动核验的异常保留在默认测试中，后续修复应新增回归用例，避免让用户再次逐个试出同一问题。
