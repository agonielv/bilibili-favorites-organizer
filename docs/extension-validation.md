# 1.3.2 验证记录（2026-11-06）

## 交付与实现

- `extension/` 为无构建步骤的 Manifest V3 运行目录；`dist/bilibili-favorites-organizer-1.3.2.zip` 仅包含运行目录。
- 落实已确认的前景毛玻璃、中性背景、完整文字标签、目录 / 范围 / 规则三栏及常驻操作区；窄窗口使用原生模态面板。
- 目录支持鼠标框选加入、Ctrl / ⌘ 反选、Esc 撤销，上下边缘按帧自动滚动，选区使用内容坐标覆盖屏幕外行。单击、键盘、触屏滑动和原生滚动条保留；筛选外选择不变，已选筛选在拖动期间固定列表，松开后一次保存。读取与执行期间锁定框选。
- 查看与勾选分离，筛选内全选、筛选外选择审查、执行确认完整来源清单；键盘焦点与字段错误关联。
- 按来源持续保留当前页缓存，新增只补读缺失来源，读取与预览不按时长过期；执行前全量重新读取并比对来源 ID、失效状态和排序信息；显式刷新、执行、账号变化清除可执行缓存。执行期间仅保留标注非实时的只读样本，不用于再次执行。
- 失效视频仍纳入完整分页计数，分组时跳过并保留在原夹；预览、执行确认、完成提示与目录残留数量一致。全失效时预览可读，执行禁用。
- 分开提交 / 完整核对，统一阶段反馈；执行期间搜索、已读查看和帮助可用。成功后复用末尾已有列表元数据同步目录；失败时标注任务前数据、未知批次与视频位置。
- 冷却倒计时只在本地更新，新网络操作禁用，不轮询、不自动续跑。保留独立标签页、双入口、可配置规则、取消不写入及请求保护。
- 新增自适应批量（2 / 20 / 100）、批次上限协商、方向校准、按成本选择私密中转、部分应用归属核对、逐条校正、全量顺序及来源核对、读取页大小协商。
- 最终确认已说明中转行为及中断后的核对要求。没有备份 / 导出、自动删除、断点恢复或一键撤销功能。

## 云端实装限制

本云实例 Chromium 明确设置 `ExtensionInstallBlocklist: ["*"]`，禁止自定义扩展，未绕过或修改该策略。因此不能把 shim 检查称作真实扩展实装；Chrome 与 Edge 的本机安装、DNR 请求头规则、Cookie 与现行 B 站接口仍需要本机验证。

## 本机验证建议

1. 先加载解压目录，在扩展管理页检查错误；分别从工具栏与 B 站收藏夹页控件打开同一管理页。
2. 在同一浏览器登录 B 站，选择少量测试收藏，验证取消后网页 / 手机 App 正常。
3. 验证时间升降序、私密 / 公开、跨源归并；观察批次和请求数，检查真实目标的完整顺序。
4. 使用交错来源测试中转，并确认成功后中转为空；中断时核对源、目标、中转三处。
5. 再逐步增加规模，记录真实读取、移动、核对耗时。出现风控时停止等待，不故意施压寻找封禁阈值。

没有提供或需要聊天中粘贴的 Cookie / CSRF。若异常，提供阶段、错误码和可见提示即可。模拟请求量下降不是实际平台耗时保证。
