# 1.1.0 验证记录（2026-11-05）

## 交付与实现

- `extension/` 为无构建步骤的 Manifest V3 运行目录；`dist/bilibili-favorites-organizer-1.1.0.zip` 仅包含运行目录。
- 保留独立标签页、双入口、可配置规则、缓存、取消不写入、限流保护及系统控件风格 UI。
- 新增自适应批量（2 / 20 / 100）、批次上限协商、方向校准、按成本选择私密中转、部分应用归属核对、逐条校正、全量顺序及来源核对、读取页大小协商。
- 最终确认已说明中转行为及中断后的核对要求。没有备份 / 导出、自动删除、断点恢复或一键撤销功能。

## 自动化检查

- 引擎 / 请求 / 分页 25 项。
- 批量传输及回退 26 项（含固定种子 100 组后端 / 来源 / 规则组合）。
- 旧脚本取消 / 限流安全回归 15 项。
- 6000 条基准的四种来源 / 页大小组合均精确核对所有 ID 和位置；数据见 `transfer-benchmark.json`。
- 实际 HTML / CSS / ES 模块的浏览器集成使用 Chrome API shim 及模拟接口，检查取消、缓存、升序、公开确认、私密创建、真正的多资源请求、账号切换、风控、原生 Web Locks、SPA 入口与后台消息范围。另增加私密中转、公开目标、反向参数顺序后端的方向校准及完整核对。
- 凭证不进入存储，接口标题按文本渲染；所有接口响应均模拟，无真实账号写入。
- 语法、ZIP 内容、图标尺寸、CRC 和 Git 空白检查。

运行命令：

```sh
npm test
npm run benchmark
BROWSER_TOOLS_DIR=/workspace/.onboarding/bilibili npm run test:browser
npm run pack
```

浏览器工具路径是本云实例已安装的工具；其他机器请按 README 安装。浏览器测试不修改管理策略。

## 云端实装限制

本云实例 Chromium 明确设置 `ExtensionInstallBlocklist: ["*"]`，禁止自定义扩展，未绕过或修改该策略。因此不能把 shim 检查称作真实扩展实装；Chrome 与 Edge 的本机安装、DNR 请求头规则、Cookie 与现行 B 站接口仍需要本机验证。

## 本机验证建议

1. 先加载解压目录，在扩展管理页检查错误；分别从工具栏与 B 站收藏夹页控件打开同一管理页。
2. 在同一浏览器登录 B 站，选择少量测试收藏，验证取消后网页 / 手机 App 正常。
3. 验证时间升降序、私密 / 公开、跨源归并；观察批次和请求数，检查真实目标的完整顺序。
4. 使用交错来源测试中转，并确认成功后中转为空；中断时核对源、目标、中转三处。
5. 再逐步增加规模，记录真实读取、移动、核对耗时。出现风控时停止等待，不故意施压寻找封禁阈值。

没有提供或需要聊天中粘贴的 Cookie / CSRF。若异常，提供阶段、错误码和可见提示即可。模拟请求量下降不是实际平台耗时保证。
